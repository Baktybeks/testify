# Приёмка перед экзаменом

## Автоматизировано

- SQL-миграции исполняются на PGlite.
- Одна попытка модуля, повтор команды не создаёт второй ответ.
- Выборка без повторов, точные квоты, отказ при нехватке темы.
- Снимок банка сохраняет оценивание при изменении источника.
- Просроченные интервалы и общий дедлайн фиксируют пропуски.
- Закрытие запрещает новые старты, сохраняет продолжение.
- Результат скрыт до публикации, публикация с активными попытками запрещена.
- Права RPC, private schema, сервисные функции, FSD-импорты.
- Мобильный E2E с mock API: вход, ответ, перезагрузка, продолжение, скрытый и опубликованный результат.

## Требует реального стенда

- [ ] Проект Supabase создан, миграции применены, Auth signup отключён.
- [ ] Edge Function развёрнута, ALLOWED_ORIGIN настроен.
- [ ] Создан преподаватель; посторонний аккаунт не получает его доступ.
- [ ] Импортированы полный список студентов и банк, коды переданы приватно.
- [ ] Два независимых PostgreSQL/HTTP-сеанса одновременно стартуют одну попытку.
- [ ] Две вкладки отправляют разные ответы на одну позицию: принят только один.
- [ ] Возврат после 2 минут отсутствия и после 600 секунд.
- [ ] Ответ возле границы дедлайна, потерянное подтверждение, повтор, офлайн.
- [ ] Реальные мобильные браузеры 320–430 px и планшет; клавиатура, screen reader.
- [ ] XLSX/CSV с дублями и ошибками блокирует импорт; частичный импорт аккаунтов восстанавливается.
- [ ] Отдельные окна групп работают в UTC с отображением Бишкек.
- [ ] GitHub Actions успешно публикует страницу после настройки variables/Pages.
- [ ] k6: 150, затем 300 студентов на новом модуле; фиксируются p95, errors, конфигурация и время.
- [ ] После нагрузки SQL проверяет число попыток, ответов, результаты и отсутствие дублей.
- [ ] Проверены backup, восстановление и мониторинг ошибок/блокировок.

Production-ready статус возможен после прохождения стендовых проверок. Без этого поставка является рабочей реализацией для подключения и приёмки, а не подтверждённой эксплуатационной гарантией.
